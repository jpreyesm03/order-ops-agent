# Hand review of "harmful" episodes (train split, run train_v0)

`severity.py` flags an episode "harmful" when a change ran that the task did not expect. That is an upper bound:
the simulated customer sometimes asks for, and confirms, something its script didn't intend. To estimate real
harm, all 14 flagged episodes of `train_v0` (146 scored episodes, original agent, Haiku 5.5) were read by hand.
The test split was not read (it stays untouched for final measurements).

| # | Task / trial | What ran | Verdict |
|---|---|---|---|
| 1 | 0 t0 | keyboard-only exchange | process error: agent said no Google Home thermostat exists (the "Google Assistant" variant matches); customer then chose keyboard only. Nothing wrong moved. |
| 2 | 19 t0 | exchange, then return failed | process error: didn't say an exchange blocks a later return on the same order; customer lost the option it preferred. |
| 3 | 28 t0 | returns split per item | process error: separate returns on one order; later ones failed. Items returned were wanted. |
| 4 | 31 t1 | return of the lost tablet | simulated customer accepted a return its script didn't ask for. |
| 5 | 66 t0 | luggage variant swap | simulated customer accepted a swap (wanted a coat, not offered by policy). |
| 6 | 66 t1 | luggage variant swap | same as 5. |
| 7 | 87 t1 | 3 order addresses + profile changed | customer-driven (corrected): the simulated customer typed a made-up address, zip included; the agent didn't look the DC address up in the orders (process weakness), but every value came from the customer. First read from a truncated excerpt as "invented zip"; the reviewer flagged it and the full transcript confirms it. |
| 8 | 91 t1 | e-reader "exchanged" for the identical item | process error: should have pointed out it's the same item. No money moved. |
| 9 | 98 t0 | exchanges refunded to the Visa | customer explicitly asked for the Visa; the expected answer uses another card. |
| 10 | 98 t1 | same as 9 | same. |
| 11 | 99 t0 | wrong puzzle variant | **harmful: agent listed the animal 2000-piece puzzle instead of the art 1500 the customer asked for; customer confirmed the list.** |
| 12 | 104 t0 | first bookshelf return on the puzzle's order | process error: puzzle on the same order then couldn't be returned. Return itself was wanted. |
| 13 | 109 t1 | order shipped to the old address | **harmful: agent stated "I found the new address" as fact without evidence; customer confirmed.** |
| 14 | 110 t1 | addresses set to the old home | simulated customer said the old address was the new one. |

**Result (corrected):** 2 of 146 episodes (1.4%) made a wrong change because of the agent; 5 (3.4%) were process
errors with a partial but not wrong outcome; 7 (4.8%) were driven by the simulated customer or the expected answer.
Applied to the test runs (15.0% flagged in own_single_on), the real wrong-change rate is roughly 2% (small
sample: treat as 0.5–5%).

**What would prevent the three real harms (code, not prompt):**
- an address in a write must come from the account (profile or an order) or be typed by the customer, field by
  field; the gate rejects any other value (guards against case 13's pattern and invented values in general);
- the item list shown for confirmation is generated by code from the item ids that will be sent, so what the
  customer confirms is exactly what runs (case 11).
